# v0.3.5 — Read-Only Customer Service Tools

v0.3.5 adds one bounded business-tool workflow: a customer verifies one order
inside the current chat, then receives a deterministic order status and latest
shipping event. The release uses a replaceable Demo Adapter and deliberately
does not implement refunds, cancellation, returns, address changes, or any
other write operation.

## Customer flow

- Deterministic routing runs before RAG: explicit human request, unsupported
  write action, private lookup, then policy question.
- A private lookup renders a bilingual inline verification card under the
  assistant message. Demo mode exposes fictional `RW-DEMO-1002 / 135790`.
- Successful verification creates a ten-minute authorization for one active
  customer session, browser identity, order, and `order_status_lookup@1`.
- The current page receives a cropped closed-enum result. Refreshing history
  shows only “lookup completed; reverify to view it again.”
- Timeout or temporary unavailability offers retry or human support without
  automatic escalation. Invalid adapter output is suppressed and sent to the
  structured `order_support` queue.

## Security and privacy

- The browser holds only a random `rw_order_grant` Cookie with `HttpOnly` and
  `SameSite=Strict`; production also sets `Secure`.
- SQLite stores the grant token hash, an AES-256-GCM encrypted order reference,
  HMAC fingerprints, bindings, and expiry. New verification revokes the old
  grant for that session.
- Verification codes never enter chat, logs, audit, URLs, or model requests.
  Order references are masked before chat persistence or downstream AI work.
- Tool audit stores masked order, tool and adapter versions, closed status,
  duration, safe error code, and timestamps. It never stores raw provider
  payloads, customer contact/payment fields, or carrier free text.
- Lookup authorization precedes idempotency replay. Unauthorized, expired,
  cross-session, cross-browser, and unsupported write paths make zero adapter
  lookup calls.

## Compatibility and operations

- `POST /api/chat` keeps all existing SSE events and adds optional `tool`
  metadata only. No bearer credential field was added.
- Verification has independent IP and session limits. Lookup requires an
  `Idempotency-Key`, permits one in-flight execution per session, and calls the
  adapter once with a three-second default deadline.
- Additive SQLite objects `order_access_grants` and `tool_executions` are safe
  on repeated startup. Startup expires old grants and marks orphaned `running`
  executions `interrupted`.
- Development and test default to Demo. Production defaults to disabled and
  requires explicit `ORDER_TOOL_PROVIDER=demo` opt-in.
- `npm run eval:tools` fixes bilingual routing, four Demo states,
  authorization, timeout, unsafe-result suppression, escalation, and leakage
  gates.

screenshots, known limits, and publication state.

## 中文说明

v0.3.5 只增加一个受控业务工具闭环：客户在当前聊天中验证单个订单，然后得到
确定性的订单状态和最新物流事件。当前使用可替换 Demo Adapter，不接真实订单
系统，也不支持退款、取消、退货、修改地址或任何写操作。

确定性路由在 RAG 前依次处理明确转人工、写操作、私有查询和政策问题。验证成功
后签发绑定当前会话、浏览器标识、单个订单和 `order_status_lookup@1` 的 10 分钟
授权。完整裁剪结果只存在当前页面；刷新历史只显示安全摘要，重新查看必须再次
验证。

浏览器 Cookie 只保存随机令牌，服务端保存令牌哈希、AES-256-GCM 加密订单号、
HMAC 指纹和绑定信息。验证码不会进入聊天、日志、审计、URL 或模型请求；后台
会话详情只展示掩码订单号、工具/适配器版本、耗时、安全错误和时间。非法适配器
结果不会展示，并创建 `order_support` 结构化转人工；超时或不可用不会自动升级。

开发和测试默认启用 Demo，生产默认禁用。显式启用后可使用虚构样例
`RW-DEMO-1002 / 135790`。新增 `npm run eval:tools` 固定验证中英文路由、授权
绑定、四种状态、超时、非法结果拒绝和零泄漏门禁。
