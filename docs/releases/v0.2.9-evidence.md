# v0.2.9 Release Evidence — Structured Escalation & Triage

## User scenario

A customer asks the bot to perform a private order operation. The bot refuses
the unsupported action, emits the existing escalation SSE event, and atomically
saves a high-priority structured handoff. An administrator opens the triage
queue, filters the order-support lane, reviews the reason and next step, and
jumps from each confirmed fact to its verbatim conversation source.

## Implemented scope

- Additive one-to-one escalation packet persistence with idempotent historical
  backfill and filter indexes.
- Versioned deterministic routing for account security, complaints, refunds,
  orders, technical issues, general support, and legacy manual triage.
- Hard safety gates preventing model output from changing priority, risk, queue,
  reason code, or next step.
- Optional two-second extraction with three response-format compatibility modes,
  exact message-ID/excerpt validation, and deterministic fallback.
- One transaction for assistant message, escalation log, packet, message marker,
  and session state.
- Authenticated, paginated, SQL-filtered list and detail APIs.
- Bilingual, light/dark, keyboard-accessible desktop and mobile admin triage UI.
- Deterministic `npm run eval:triage` coverage and API/browser regression tests.

## Independent adversarial review

Separate standards and specification reviews examined security, transaction
consistency, compatibility, SQL performance, prompt injection, and fresh-clone
behavior. Their actionable findings were fixed before the final verification:

- latest-per-session ranking now happens before category, queue, priority, and
  keyword filters, preventing an older matching handoff from resurfacing;
- compound session/time and status/time indexes cover the queue ordering path;
- model extraction is independently capped by a two-second outer deadline and
  receives only the latest 12 messages;
- extraction logs retain only safe identifiers, response format, and error
  type, never provider error text or conversation content;
- invalid model facts are discarded individually, while protected-field or
  schema violations still trigger complete deterministic fallback;
- persisted fact, risk, missing-information, and evidence arrays are validated
  on read with empty-array fallback for malformed historical JSON;
- fact-source navigation now scrolls and moves keyboard focus to the cited
  message.

No blocking security, data-consistency, compatibility, SQL-performance,
prompt-injection, or fresh-clone issue remained after the fixes and complete
verification.

## Known limits

- This is read-only triage, not human takeover or case management.
- There are no assignment, ownership, internal notes, resolution, SLA, or
  business-action mutations.
- Optional extraction is synchronous and never retried after the two-second
  total budget.
- The extraction context is intentionally limited to the latest 12 messages;
  older turns remain available in the administrator transcript but are not sent
  to the optional packet extractor.
- Historical rows have no reconstructed facts or evidence.
- SQLite and the in-process runtime remain the default open-source deployment.
